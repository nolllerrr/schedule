# Формат Excel и проверка импорта

Бот рассчитан на структуру Excel расписания техникума, а не на произвольную таблицу. Поиск файла реализован в [`downloader.py`](../src/schedule_bot/downloader.py), распознавание расписания — в [`parser/excel.py`](../src/schedule_bot/parser/excel.py), чтение XLSX — в [`parser/workbook.py`](../src/schedule_bot/parser/workbook.py).

## Выбор публикации

Загрузчик ищет заголовок «Расписание занятий», следующую область `div.content` и таблицу в ней. При отсутствии заголовка он пробует первую таблицу страницы. Для корпуса 1 рассматривается первый столбец `td`; ссылки других корпусов не объединяются.

Рассматриваются `.xlsx` с распознаваемой датой или диапазоном в имени. В окно `PUBLICATION_LOOKBACK_DAYS` / `PUBLICATION_LOOKAHEAD_DAYS` публикация попадает по диапазону в имени или распознанной датированной подписи ссылки. Число файлов ограничено `PUBLICATION_MAX_FILES`. Если окно пусто, проверяется самая поздняя публикация по имени файла. Полного обхода всего архива нет.

Для каждой распознанной даты приоритет получает публикация с более узким подтверждённым диапазоном. Различающиеся публикации одинаковой ширины диапазона дают конфликт и карантин. Если для прежде принятой даты кандидатов больше нет, её сохранённое расписание остаётся активным. Порядок ссылок и HTTP-время изменения приоритет не определяют. Исправление раннего файла обнаруживается, даже когда более поздний файл не менялся.

Служебная ссылка `/_/static/...nubex.ru/...` преобразуется в прямой HTTPS-адрес разрешённого домена Nubex. Файл скачивается во временный `.part`, проверяется начальная ZIP-сигнатура и считается SHA-256. Итоговое имя содержит первые 12 символов SHA и имя файла. Полная проверка ZIP/XLSX выполняется при чтении книги.

При повторной проверке URL используются ETag/Last-Modified, если сервер их прислал. Ответ HTTP 304 сохраняет байты и использует подпись с текущей страницы. Снимок определяется SHA-256 и подтверждённым диапазоном, поскольку одинаковые байты с разными диапазонами могут выбирать разные листы. При согласованных датах известный снимок читается без разбора, в том числе после перезапуска. При конфликте подписи и имени книга проверяется заново даже при HTTP 304. Переименование того же файла источником в соответствии с подтверждённой датой использует тот же снимок и не создаёт повторную рассылку.

## Имя файла и листы

Поддерживаются, например:

| Имя | Диапазон |
| --- | --- |
| `05.10.2026.xlsx` | 05.10.2026 |
| `14.09.26-18.09.26.xlsx` | 14–18.09.2026 |
| `21.-23.09.2026.xlsx` | 21–23.09.2026 |
| `28.-01.10.2026.xlsx` | 28.09–01.10.2026 |
| `28.09.-02.10.2026.xlsx` | 28.09–02.10.2026 |
| `30.12.-02.01.2027.xlsx` | 30.12.2026–02.01.2027 |

При локальном импорте имя должно содержать дату или диапазон. Сетевой парсер получает исходное имя файла и сведения о датированной подписи ссылки.

Дата листа распознаётся из названия вроде `22 сентября 2026` или `22.09.2026`. При согласованных датах или нейтральной подписи действует диапазон имени файла. Листы вне диапазона не читаются, листы без распознанной даты дают предупреждение. Скрытый лист с подходящей датой также рассматривается. Из нескольких блоков выбирается наиболее заполненный блок соответствующего дня недели.

При конфликте подписи и имени бот использует даты подписи только при выполнении всех условий.

1. Подпись задаёт один однозначный диапазон или день. Две разные датированные подписи одного URL считаются конфликтом.
2. Каждая дата подписи указана в точном названии единственного видимого листа. Ни один лист не подтверждает диапазон имени файла. Прочие листы должны быть скрытыми и датироваться раньше начала диапазона подписи.
3. Все целевые листы проходят структурную проверку и содержат занятия либо подтверждённый пустой день. Дата занятия берётся из названия листа. Восстановленная публикация затем проходит обычные проверки импорта, охвата и приоритета.

По этому правилу книгу `26.-27.11.2026.xlsx` можно принять как публикацию на 23 ноября, если ссылка подписана `23.11.2026г.`, лист за 23 ноября видим, а дополнительные листы за 10–13 ноября скрыты. Исходное имя сохраняется в снимке, а его диапазон соответствует подтверждённому 23 ноября.

## Сетка занятий

- Заголовки групп ищутся в первых 20 строках, начиная с колонки C. Группа занимает четыре столбца; названия нормализуются, например `Т -21` → `Т-21`.
- В колонке A определяется день недели, в B — метка `1 пара`, `2 пара` и т. п. либо `кл.час`.
- Один блок занятия занимает четыре строки. Предмет и преподаватель читаются из первых трёх столбцов группы в соответствующих половинах блока, аудитория — из четвёртого столбца в верхней половине.
- Поиск внутри выбранного дня ограничивается следующим днём недели либо окном в 33 строки. Произвольная высота и ширина блоков не поддерживаются.
- Время берётся из ячейки под меткой пары; фиксированного расписания звонков в коде нет. Нераспознанное время остаётся `None`.
- Подгруппы 1/2 распознаются из явных пометок предмета и поддерживаемого вертикального или горизонтального расположения ячеек. Каждая часть сохраняет собственные предмет, преподавателя и аудиторию; общее значение используется только при однозначной общей ячейке. Несовместимая геометрия или потерянная связь частей дают структурную ошибку, значения не перемешиваются.
- `raw_data` хранит координаты и нормализованные текстовые значения непустых ячеек блока 4×4. Это диагностическое представление, а не копия оформления и исходных пробелов Excel.

Объединения ячеек учитываются: значения внутренних ячеек объединённой области отбрасываются, остаётся значение верхней левой. Формулы не вычисляются — читается сохранённый в книге результат; формула без кешированного значения даёт пустое значение. Поддерживаются общие строки, rich text, даты и время с учётом эпохи Excel.

## Проверка перед активацией

Парсер возвращает занятия, распознанные даты, охват заголовков групп, предупреждения и структурные ошибки. [`validate_import`](../src/schedule_bot/import_validation.py) проверяет каждый источник и затем собранное активное расписание. Для известной URL учитывается её прежний снимок; для активации — текущие занятия и сохранённый охват, включая группы ранее пустого дня. Сохранённый проигрывающий снимок не может обойти проверку, когда снова становится победителем.

| Ситуация | Результат |
| --- | --- |
| Не распознаны заголовок группы, день или блок пары; неверна ширина блока | Структурная ошибка |
| Преподаватель или аудитория есть, а предмет отсутствует | Структурная ошибка |
| Повторяется ключ занятия, дата противоречит диапазону или заголовкам | Структурная ошибка |
| В пределах нового диапазона пропала ранее опубликованная дата или ожидаемая группа | Аномалия охвата, требуется проверка |
| У дня или группы исчезли все занятия | Аномалия количества, если нет допустимого подтверждения пустого дня |
| Количество занятий дня или группы сократилось минимум вдвое при прежних четырёх и более | Аномалия количества |
| Обычное сокращение, не попадающее под эти условия | Может быть принято автоматически |

Ожидаемый охват включает ранее опубликованные группы и группы, распознанные на других датах этой книги. Зеркальная таблица звонков справа учитывается как граница сетки, а не как пропавший заголовок группы.

Структурные ошибки и неподтверждённые аномалии помещают разобранный результат в карантин. Активное расписание и очередь публикации не меняются. Ошибка, не позволяющая получить `ParsedSchedule`, например повреждённый ZIP или отсутствие подходящих листов, завершает разбор раньше и не обязательно создаёт запись карантина.

Для явно пустого дня поддерживается `ЗАНЯТИЙ НЕТ` в A1. Дата, заголовки групп и блок дня должны оставаться распознаваемыми, а занятий быть не должно. Противоречие маркера и занятий блокирует импорт. Такой маркер применяется к дню целиком, а не к отдельной группе.

После проверки исходника аномалии охвата/количества можно принять с `--approval-reason`. Ошибки структуры и конфликт разных публикаций одинакового приоритета этим параметром не обходятся. [Команда и порядок действий](operations.md#карантин-импорта).

## Бюджет чтения

При сетевом обновлении весь разбор выбранных публикаций ограничен также общим бюджетом 120 секунд; отдельная книга — 60 секундами. Истечение срока останавливает дочерний процесс и сохраняет прежнюю активную версию.

Значения задаёт `WorkbookLimits` в коде; переменных `.env` для них нет.

| Ограничение | Значение по умолчанию |
| --- | --- |
| Скачанная HTML-страница | 2 МиБ |
| Скачанный файл и XLSX-архив | 20 МиБ |
| ZIP-записи | 256 |
| Сумма распакованных частей | 128 МиБ |
| Одна распакованная часть | 32 МиБ |
| Метаданные / центральный каталог ZIP | 1 МиБ |
| Листы книги | 32 |
| Размер читаемого листа | 4096 строк × 512 столбцов |
| Прочитанные XML-ячейки суммарно | 2 000 000 |
| Ячейки со значениями на листе | 100 000 |
| Общие строки | 100 000 |
| Текст, учитываемый читателем | 2 000 000 символов суммарно, до 32 767 в одном значении |
| Форматы / стили | 200 000 |
| Объединённые области на листе | 20 000; суммарная площадь ограничена 2 000 000 ячеек |
| Вложенность XML / узлы одного читаемого значения | 64 уровня / 4096 узлов |
| Вся сетевая часть одной проверки публикаций | 300 секунд |
| Одна HTTP-попытка, включая чтение и редиректы | 30 секунд |
| Разбор одного файла стандартным парсером при сетевом обновлении или CLI `parse` | 60 секунд в отдельном процессе |

Объявления XML-сущностей, дубли ZIP-частей и неверные ссылки на части отклоняются. Лимиты листов и распакованного архива относятся к книге целиком, даже если часть её листов не нужна по датам; лимиты прочитанных ячеек относятся к обработанным листам.

Загрузка проверяет размер по ходу чтения и после HTTP-распаковки gzip/deflate, даже без корректного `Content-Length`. Тела редиректов не загружаются, неполные временные файлы удаляются при сбое или отмене. Превышение бюджета останавливает импорт целиком. Стандартный парсер сетевого обновления выполняется в отдельном процессе; по дедлайну или отмене процесс завершается. CLI `parse` использует тот же процессный дедлайн. Локальный `import-file` использует размерные бюджеты, но выполняется синхронно без этого дедлайна. Расширять бюджет следует в коде после проверки реального формата и тестов.
