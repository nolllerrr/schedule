# Формат Excel и проверка импорта

Бот рассчитан на структуру Excel расписания техникума, а не на произвольную таблицу. Поиск файла реализован в [`downloader.py`](../src/schedule_bot/downloader.py), распознавание расписания — в [`parser/excel.py`](../src/schedule_bot/parser/excel.py), чтение XLSX — в [`parser/workbook.py`](../src/schedule_bot/parser/workbook.py).

## Выбор публикации

Загрузчик ищет заголовок «Расписание занятий», следующую область `div.content` и таблицу в ней. При отсутствии заголовка он пробует первую таблицу страницы. Для корпуса 1 рассматривается первый столбец `td`; ссылки других корпусов не объединяются.

Из ссылок выбираются `.xlsx` с распознаваемой датой или диапазоном в имени. Приоритет — наиболее поздняя дата окончания, затем начала диапазона. Это выбор по датам файла, а не по HTTP-времени изменения. За один проход загружается один выбранный файл: полного обхода архива старых публикаций нет.

Служебная ссылка `/_/static/...nubex.ru/...` преобразуется в прямой HTTPS-адрес разрешённого домена Nubex. Файл скачивается во временный `.part`, проверяется начальная ZIP-сигнатура и считается SHA-256. Итоговое имя содержит первые 12 символов SHA и имя файла. Полная проверка ZIP/XLSX выполняется при чтении книги.

При повторной проверке того же URL используются ETag/Last-Modified, если сервер их прислал. Этот HTTP-кеш живёт в процессе; проверка уже импортированного SHA опирается на SQLite и работает после перезапуска. Принятый SHA пропускается до парсера, карантинный — проверяется заново.

## Имя файла и листы

Поддерживаются, например:

| Имя | Диапазон |
| --- | --- |
| `05.10.2026.xlsx` | 05.10.2026 |
| `14.09.26-18.09.26.xlsx` | 14–18.09.2026 |
| `21.-23.09.2026.xlsx` | 21–23.09.2026 |
| `28.-01.10.2026.xlsx` | 28.09–01.10.2026 |
| `28.09.-02.10.2026.xlsx` | 28.09–02.10.2026 |
| `30.12.-02.01.2027.xlsx` | 30.12.2026–02.01.2027 |

При локальном импорте сохраняйте в имени дату или диапазон; `schedule.xlsx` без даты не подходит. При сетевой загрузке парсеру передаётся исходное имя ссылки.

Дата листа распознаётся из названия вроде `22 сентября 2026` или `22.09.2026`. Листы вне диапазона имени файла не читаются; листы без распознанной даты дают предупреждение. Из нескольких блоков выбирается соответствующий дню недели даты листа и наиболее заполненный.

Видимость листа сама по себе не является фильтром: текущий читатель не исключает `hidden`/`veryHidden`. Скрытый лист с подходящей датой также рассматривается. Данные шаблона отбрасываются за счёт диапазона и выбора блока дня, а не гарантированно по признаку скрытия.

## Сетка занятий

- Заголовки групп ищутся в первых 20 строках, начиная с колонки C. Группа занимает четыре столбца; названия нормализуются, например `Т -21` → `Т-21`.
- В колонке A определяется день недели, в B — метка `1 пара`, `2 пара` и т. п. либо `кл.час`.
- Один блок занятия занимает четыре строки. Предмет и преподаватель читаются из первых трёх столбцов группы в соответствующих половинах блока, аудитория — из четвёртого столбца в верхней половине.
- Поиск внутри выбранного дня ограничивается следующим днём недели либо окном в 33 строки. Произвольная высота и ширина блоков не поддерживаются.
- Время берётся из ячейки под меткой пары; фиксированного расписания звонков в коде нет. Нераспознанное время остаётся `None`.
- Несколько уникальных значений предмета, преподавателя или аудитории объединяются строкой. Подгруппы 1/2 распознаются из пометок предмета.
- `raw_data` хранит координаты и нормализованные текстовые значения непустых ячеек блока 4×4. Это диагностическое представление, а не копия оформления и исходных пробелов Excel.

Объединения ячеек учитываются: значения внутренних ячеек объединённой области отбрасываются, остаётся значение верхней левой. Формулы не вычисляются — читается сохранённый в книге результат; формула без кешированного значения даёт пустое значение. Поддерживаются общие строки, rich text, даты и время с учётом эпохи Excel.

## Проверка перед активацией

Парсер возвращает занятия, распознанные даты, охват заголовков групп, предупреждения и структурные ошибки. [`validate_import`](../src/schedule_bot/import_validation.py) дополнительно сравнивает результат с уже принятыми данными.

| Ситуация | Результат |
| --- | --- |
| Не распознаны заголовок группы, день или блок пары; неверна ширина блока | Структурная ошибка |
| Преподаватель или аудитория есть, а предмет отсутствует | Структурная ошибка |
| Повторяется ключ занятия, дата противоречит диапазону или заголовкам | Структурная ошибка |
| В пределах нового диапазона пропала ранее опубликованная дата или ожидаемая группа | Аномалия охвата, требуется проверка |
| У дня или группы исчезли все занятия | Аномалия количества, если нет допустимого подтверждения пустого дня |
| Количество занятий дня или группы сократилось минимум вдвое при прежних четырёх и более | Аномалия количества |
| Обычное сокращение, не попадающее под эти условия | Может быть принято автоматически |

Ожидаемый охват включает ранее опубликованные группы и группы, распознанные на других датах этой книги. Зеркальная таблица звонков справа учитывается как граница сетки, а не как пропавший заголовок группы.

Структурные ошибки и неподтверждённые аномалии помещают разобранный результат в карантин. Активное расписание и очередь публикации не меняются. Ошибка, не позволяющая получить `ParsedSchedule`, например повреждённый ZIP или отсутствие подходящих листов, завершает разбор раньше и не обязательно создаёт запись карантина.

Для явно пустого дня поддерживается `ЗАНЯТИЙ НЕТ` в A1. Дата, заголовки групп и блок дня должны оставаться распознаваемыми, а занятий быть не должно. Противоречие маркера и занятий блокирует импорт. Такой маркер применяется к дню целиком, а не к отдельной группе.

После проверки исходника аномалии охвата/количества можно принять с `--approval-reason`. Ошибки структуры этим параметром не обходятся. [Команда и порядок действий](operations.md#карантин-импорта).

## Бюджет чтения

Значения задаёт `WorkbookLimits` в коде; переменных `.env` для них нет.

| Ограничение | Значение по умолчанию |
| --- | --- |
| Скачанная HTML-страница | 2 МиБ |
| Скачанный файл и XLSX-архив | 20 МиБ |
| ZIP-записи | 256 |
| Сумма распакованных частей | 128 МиБ |
| Одна распакованная часть | 32 МиБ |
| Метаданные / центральный каталог ZIP | 1 МиБ |
| Листы книги | 32 |
| Размер читаемого листа | 4096 строк × 512 столбцов |
| Прочитанные XML-ячейки суммарно | 2 000 000 |
| Ячейки со значениями на листе | 100 000 |
| Общие строки | 100 000 |
| Текст, учитываемый читателем | 2 000 000 символов суммарно, до 32 767 в одном значении |
| Форматы / стили | 200 000 |
| Объединённые области на листе | 20 000; суммарная площадь ограничена 2 000 000 ячеек |
| Вложенность XML / узлы одного читаемого значения | 64 уровня / 4096 узлов |

Объявления XML-сущностей, дубли ZIP-частей и неверные ссылки на части отклоняются. Лимиты листов и распакованного архива относятся к книге целиком, даже если часть её листов не нужна по датам; лимиты прочитанных ячеек относятся к обработанным листам.

Загрузка проверяет размер по ходу чтения и после HTTP-распаковки gzip/deflate, даже без корректного `Content-Length`. Тела редиректов не загружаются, неполные временные файлы удаляются при сбое или отмене. Превышение бюджета останавливает импорт целиком. Расширять бюджет следует в коде после проверки реального формата и тестов.
