# Карточки расписания

В личном чате выберите профиль студента, откройте `/menu` → «Сегодня», «Завтра», выбранную дату или день из «Недели» → **«🖼 Карточка»**. В настроенном групповом чате путь тот же; кнопки меню доступны открывшему его участнику. При просмотре дня через нижнюю клавиатуру в личке появляется дополнительное сообщение с кнопкой карточки. Для «Недели» можно выбрать день отдельной inline-клавиатурой.

Бот отправляет PNG новым фото-сообщением. Текст и меню остаются доступны. Каждое нажатие заново получает текущие занятия через существующий `lessons_for`: группа или роль в callback не передаются. Если профиль или группа чата изменились, используются текущие настройки SQLite. Callback содержит владельца меню и ISO-дату, укладывается в лимит 64 байта.

## Дизайн и данные

Все карточки имеют размер **1080 × 1350**, тёмно-синий фон, голубую шкалу и шесть одинаковых слотов 01–06. Координаты слотов не зависят от числа занятий: верхняя граница `470 + (номер − 1) × 128`, высота 116 пикселей. Номер берётся из `lesson_number`, а не `position`. Свободные слоты остаются на месте; окна считаются только между первой и последней занятыми парами. Занятие не объявляется отменённым по отсутствию в снимке.

На момент разработки в локальной SQLite у текущих занятий встречались номера 1–5 и классные часы, поэтому общая сетка из шести слотов достаточна для этих данных. Седьмая, восьмая и другие неподдерживаемые пары вызывают пояснение и переход к текстовому виду: занятия не скрываются. Для изменения сетки нужно изменить версию шаблона и проверить читаемость всех демонстраций.

Время берётся исключительно из `Lesson`. Общий интервал показывается при известных корректных временах всех обычных пар. Неизвестные значения обозначаются явно. Классный час размещается в отдельной плашке под сеткой и не увеличивает количество пар. До двух подгрупп показываются отдельными секциями внутри одного слота: предмет, преподаватель, аудитория и подгруппа сохраняют связь.

При слишком длинных полях, неподдерживаемых символах, неоднозначной нумерации, повторном номере, большем количестве подгрупп или нехватке места PNG не создаётся. Рендерер измеряет текст встроенным шрифтом и не обрезает сведения многоточием. Пустая выборка, включая неизвестную дату, получает текстовое пояснение вместо карточки с неподтверждённым выходным.

В профиле **преподавателя кнопка скрыта** в v1: его день может содержать несколько групп на одной позиции, а макет рассчитан на одну учебную группу. Преподавательское текстовое расписание продолжает работать. Рассылки, outbox, закрепления и Grok сохраняют прежний текстовый формат.

Предупреждение о давности вычисляется через `with_freshness` при каждой отправке и находится только в подписи Telegram. Оно не сохраняется внутри PNG или в ключе кеша. Подпись короткая, без HTML и пользовательских полей. Карточка не содержит выдуманного времени обновления.

## Модули и ограничения ресурсов

| Файл | Назначение |
| --- | --- |
| `src/schedule_bot/card_renderer.py` | Чистое преобразование `Lesson` в модель слотов, затем Pillow → PNG bytes; без SQLite, Telegram и сети |
| `src/schedule_bot/card_service.py` | Общий для пользователей кеш и ограничение фонового рендера |
| `src/schedule_bot/bot/cards.py` | Проверка действия, чтение текущего расписания, подпись и отправка фото, обработка ошибок |
| `src/schedule_bot/bot/{app,groups,menus}.py` | Кнопки и существующие проверки владельца и профиля |
| `src/schedule_bot/assets/fonts/` | Noto Sans Regular/SemiBold, OFL 1.1, источники и контрольные суммы |

Pillow выполняется через `asyncio.to_thread`. В одном процессе одновременно работают максимум **2 генерации**, очереди новых ключей нет: при занятости пользователь получает предложение повторить запрос. На один ключ допускается максимум **8 ожидающих запросов**, разделяющих одну генерацию. Дедлайн ответа — **8 секунд**. Таймаут или отмена запроса не освобождает слот до фактического завершения потока: следующие запросы не создают лишних фоновых работ. При штатной остановке бот дожидается этих работ.

LRU хранит максимум **32 PNG и 16 МиБ суммарных PNG-байтов**, вытесняя самые давно использованные. Это лимит самих изображений; память Python, Pillow, шрифтов и двух рабочих изображений учитывается отдельно. Ключ включает версию шаблона, роль, группу, дату и фактические данные занятий и связанных подгрупп. Telegram ID и исходные Excel-ячейки в ключ не входят. Значимые изменения дают другой ключ; неизменные данные переиспользуют одинаковые bytes между пользователями. Кеш исчезает после перезапуска, файловой очистки не требует.

До сериализации ограничены число занятий, подгрупп и длины полей, до рисования — точное соответствие группы/даты и допустимость модели. Ошибки карточек перехватываются отдельно и логируются только по классу исключения. Новые настройки окружения, таблицы SQLite, сервисы и внешние API не нужны.

## Предпросмотр и проверка

Из корня проекта с установленными зависимостями:

```powershell
.venv/Scripts/python.exe scripts/preview_schedule_cards.py
.venv/Scripts/python.exe -m pytest --basetemp=.pytest-tmp-cards
.venv/Scripts/python.exe -m ruff check --select F src tests scripts
.venv/Scripts/python.exe scripts/update_locks.py --check
.venv/Scripts/uv.exe build --wheel --out-dir data/card-build
```

Для Linux используйте `.venv/bin/python` и `.venv/bin/uv`. Скрипт предпросмотра печатает фактическое время генерации и размер каждого файла. Данные, имена и времена в демо синтетические; рабочую SQLite он не открывает.

| Пример | Что проверить |
| --- | --- |
| [Ко второй паре](examples/schedule-cards/second-pair.png) | Слот 01 пустой, пары находятся в 02 и 03, окон 0 |
| [Окно между парами](examples/schedule-cards/gap-between-pairs.png) | Пары 02 и 04, пустой слот 03, ровно одно окно |
| [Плотный день](examples/schedule-cards/dense-day.png) | Все шесть слотов на тех же координатах, длинные названия помещаются |

Фактический локальный замер `CardService` (Windows, Python 3.12.10, Pillow 12.3.0; один прогон под нагрузкой тестов):

| Пример | PNG, байт | Создание через сервис, мс | Повтор из кеша, мс |
| --- | ---: | ---: | ---: |
| Ко второй паре | 75 451 | 120,90 | 0,124 |
| Окно между парами | 79 854 | 90,03 | 0,128 |
| Плотный день | 112 850 | 136,57 | 0,412 |

После трёх запросов кеш содержал 3 изображения / **268 155 байт**; повторные запросы вернули те же объекты bytes. Это локальные замеры, скорость VPS и Telegram ими не измеряется. Read-only проверка текущей локальной SQLite успешно отрисовала в памяти все 168 непустых расписаний групп; реальные PNG не сохранялись.

Проверка реализации: полный `pytest` — **696 passed, 2 skipped** (82,67 с); Ruff F, `compileall`, проверка зависимостей и lock-экспортов прошли. Wheel собран и установлен в отдельный каталог: проверены импорт бота, наличие лицензии/шрифтов и рендер кириллицы 1080×1350 из установленного пакета. Docker CLI в среде отсутствовал, поэтому сборка контейнера и настоящий Telegram/VPS здесь не проверялись.

В тестах используются синтетические `Lesson`, временные SQLite и подмены Telegram: проверяются нумерация, связанные подгруппы, классные часы, текстовый fallback, владельцы меню, ошибки отправки, актуальность подписи, кеш, single-flight, таймауты, отмена и работа event loop во время рендера.

Шрифты поставляются внутри wheel, поэтому контейнер не зависит от системных шрифтов. Pillow закреплён в `uv.lock`, runtime/dev экспорты обновляются штатным `scripts/update_locks.py`. Docker выполняет локальный smoke check рендера кириллицы после установки пакета; дополнительных загрузок шрифта при запуске нет.

После разрешённого деплоя на VPS проверьте карточку в личке и настроенной группе, возврат к меню, отказ чужому владельцу, подпись при устаревшем источнике и новую картинку после исправления аудитории. Отдельно проверьте, что уведомления, закрепление и Grok по-прежнему приходят текстом. Команды сборки без деплоя:

```sh
docker build --target core -t schedule-bot:cards-core .
docker build -t schedule-bot:cards .
docker run --rm --network none --entrypoint python schedule-bot:cards-core -c "from schedule_bot.bot.app import run_bot; from schedule_bot.card_renderer import IMAGE_SIZE; assert IMAGE_SIZE == (1080,1350)"
```
