# Карточки расписания

Расписание дня по умолчанию открывается карточкой: «Щас», «Сегодня», «Завтра», «Следующий день», выбор даты, дня из недельного списка и новые публикации. Это работает для студентов и преподавателей, в личке и в настроенном групповом чате. Кнопка **«Текст»** отправляет полное расписание и после успешной отправки удаляет исходную карточку. Длинный текст разбивается на части без потери полей, кнопка находится под последней частью; карточка удаляется только после отправки всех частей. Кнопка **«Карточка»** под текстом отправляет изображение и после успешной отправки удаляет текстовое сообщение с кнопкой. Если карточку отправить не удалось, текст остаётся. Если карточка недоступна, исходный ответ содержит полный текст с кнопкой «Карточка».

Карточка отправляется обычным [sendPhoto](https://core.telegram.org/bots/api#sendphoto), чтобы Telegram подбирал размер сообщения под изображение. Фото-блок внутри Rich Message давал более широкую рамку с полями. Текст отправляется через `sendMessage`; при переключении в любом направлении исходное сообщение удаляется через `deleteMessage` после доставки нового вида. Если Telegram отклоняет удаление, новый вид остаётся доступным, а ошибка логируется только по классу. PNG создаётся прежним `CardService`; дополнительного кеша или состояния пользователя для переключения нет. Кнопки в ранее отправленных Rich Message работают по тем же правилам.

В настроенном групповом чате `/menu` сразу открывает карточку актуального дня для группы чата по тем же правилам, что и «Щас» в личке. «Текст» и «Карточка» переключают вид с удалением предыдущего сообщения после доставки нового. Кнопки доступны участнику, вызвавшему `/menu`; его личный профиль не используется. Под обоими видами находится кнопка «Меню расписания» для перехода к другим датам и настройкам чата. Если ближайшего расписания нет, бот сообщает об этом и показывает обычное меню.

Через меню можно выбрать «Сегодня», «Завтра», дату или день из «Недели»: выбранный день сразу открывается карточкой с удалением предыдущего сообщения меню после доставки нового вида. Неделя предлагает список дней для открытия карточками.

Уведомление **«Опубликовано новое расписание»** приходит карточкой каждого нового дня с кнопкой «Текст». Очередь SQLite хранит снимок занятий из принятого импорта без исходных Excel-ячеек. Рендер выполняется при доставке; повторная отправка не подменяет снимок текущим расписанием. При недоступности рендера отправляются сохранённые текстовые части, кнопка находится под последней. Если одна карточка заменяет несколько текстовых частей, они атомарно отмечаются доставленными только после успешного ответа Telegram. Перечень изменений уже опубликованного дня и комментарии Grok остаются текстовыми.

В групповом уведомлении открыть текст или меню может любой участник, после чего кнопки привязываются к нему. Настройки по-прежнему требуют прав администратора. Закреплённый день также отправляется фото, без персональных кнопок; изменения того же дня обновляют медиа. При невозможности рендера используется полный текст.

Каждое нажатие заново получает текущие занятия через существующий `lessons_for`: группа или роль в callback не передаются. Дата на кнопке переключения сохраняется и после смены дня; профиль и группа берутся из текущих настроек SQLite. В личке используется профиль пользователя, в группе — активный профиль чата. Callback содержит владельца меню и ISO-дату, укладывается в лимит 64 байта. Чужой пользователь не может переключить вид. При ошибке отправки текущее сообщение сохраняется, а callback получает пояснение; исключения логируются только по классу.

## Дизайн и данные

Карточки без классного часа имеют размер **1080 × 1444**, RGB; с классным часом — **1080 × 1620**. Вариант «Акцент на аудитории» использует пять слотов **01–05**, как в таблицах Excel, рисуется в двойном разрешении, затем уменьшается LANCZOS. Фон — `#0C191E`, основной текст — `#F4F8F8`, вторичный — `#9EAFB4`, акцент — `#83DFD5`. Базовые координаты слотов: верхняя граница `510 + (номер − 1) × 176`, высота 160, границы по горизонтали `136…1024`. Номер слева берётся из `lesson_number`, а не `position`. Свободные слоты остаются на месте и содержат тире. Занятие не объявляется отменённым по отсутствию в снимке. Версия шаблона — `schedule-cards-v3.4-five-slots`.

Классный час вставляется отдельной карточкой **без номера** в порядке исходного расписания (`Lesson.position`). Например, между 02 и 03; последующие слоты сдвигаются вниз на 176 px, сохраняя свои номера и размеры. Пустые ранние слоты, неизвестное время и день с одним классным часом поддерживаются. В его карточке сохраняются время, преподаватель и помещение; если предмет содержит отдельную тему, она добавляется к заголовку «Классный час». Счётчик и общий интервал обычных пар не включают классный час. Несколько классных часов или неоднозначный порядок занятий переводят день в полный текстовый вид.

В шапке находятся группа, дата и день недели выбранного расписания. Две плашки показывают число реальных пар с правильным склонением и общий интервал занятий. Отдельной статистики окон, вертикальной шкалы, соединительных точек и полосок нет. Краткая характеристика дня зависит от нагрузки. Пять пар обозначаются как плотный учебный день; короткое расписание не получает такую подпись.

Предмет рисуется Nimbus Sans Bold, базовый размер 43 px, верхняя граница — на 32 px ниже верха слота. Длинное название переносится максимум на две строки с измерением полной высоты глифов: для них доступны 68 px до строки помещения и преподавателя, с зазором не меньше 2 px. Внизу слева — плашка помещения и преподаватель, справа — время. Числовой номер аудитории выделен белым жирным шрифтом 27 px; приглушённый суффикс ` ауд.` расположен на 5 px ниже. `спортзал` остаётся обычным приглушённым текстом без суффикса. Существующие `ауд.`/`аудитория` нормализуются без дублирования; обозначения вроде `24а` сохраняются. При отсутствии помещения плашка не рисуется.

Время берётся исключительно из `Lesson.start_time/end_time`, которые заполняются действующим парсером Excel. Общий интервал показывается при известных корректных временах всех обычных пар. Неизвестные значения обозначаются явно. Демонстрационные часы не являются общим расписанием звонков.

Одна подгруппа в слоте поддерживается, в том числе для классного часа. Её обозначение сохраняется в названии предмета (`ДОУ 2 п/гр`); если такого обозначения нет, к заголовку добавляется `· подгр. 2`. Полный заголовок измеряется вместе с меткой, без обрезки и дублирования уже указанной подгруппы.

Шестая и последующие пары, несколько занятий или параллельные подгруппы в одном слоте получают существующий текстовый fallback. Это относится и к классному часу с несколькими подгруппами. Их сведения не отбрасываются ради PNG: исходное текстовое расписание сохраняет предметы, преподавателей, помещения, время и связи подгрупп.

При слишком длинных полях, неподдерживаемых символах, неоднозначной нумерации, повторном номере, большем количестве подгрупп или нехватке места PNG не создаётся. Рендерер измеряет текст встроенным шрифтом и не обрезает сведения многоточием. Пустая выборка, включая неизвестную дату, получает текстовое пояснение вместо карточки с неподтверждённым выходным.

У преподавателя используется отдельный макет списка занятий: ФИО и дата в шапке, предмет, группа, аудитория и время в каждой строке. Одновременные группы сохраняются отдельными строками. Связанные подгруппы сначала фильтруются по преподавателю; чужие назначения не попадают в карточку. Поддерживается до 24 строк, размер — 1080 × (420 + 220 × число строк). [Пример](examples/schedule-cards/teacher-day.png).

Дублирующая подпись «Расписание · дата» под картинкой не отправляется: дата уже есть внутри PNG. Подпись появляется только при необходимости предупредить о давности или неподтверждённой актуальности данных. Предупреждение вычисляется через `with_freshness` при каждой отправке и переключении вида, без HTML и пользовательских полей. Оно не сохраняется внутри PNG или в ключе кеша. Карточка не содержит выдуманного времени обновления.

## Модули и ограничения ресурсов

| Файл | Назначение |
| --- | --- |
| `src/schedule_bot/card_renderer.py` | Чистое преобразование `Lesson` в модель слотов, затем Pillow → PNG bytes; без SQLite, Telegram и сети |
| `src/schedule_bot/card_service.py` | Общий для пользователей кеш и ограничение фонового рендера |
| `src/schedule_bot/schedule_media.py` | Восстановление снимка занятий и подготовка фото для очереди и закреплений |
| `src/schedule_bot/schedule_controls.py` | Общие кнопки для просмотра и рассылки без импорта роутеров |
| `src/schedule_bot/bot/cards.py` | Проверка действия, чтение текущего расписания, подпись и отправка фото, обработка ошибок |
| `src/schedule_bot/bot/{app,groups,menus}.py` | Кнопки и существующие проверки владельца и профиля |
| `src/schedule_bot/assets/fonts/` | Nimbus Sans Regular/Bold, исходная лицензия `FONT_LICENSE.txt`, источники и контрольные суммы |

Pillow выполняется через `asyncio.to_thread`. В одном процессе одновременно работают максимум **2 генерации**, очереди новых ключей нет: при занятости пользователь получает предложение повторить запрос. На один ключ допускается максимум **8 ожидающих запросов**, разделяющих одну генерацию. Дедлайн ответа — **8 секунд**. Таймаут или отмена запроса не освобождает слот до фактического завершения потока: следующие запросы не создают лишних фоновых работ. При штатной остановке бот дожидается этих работ.

LRU хранит максимум **32 PNG и 16 МиБ суммарных PNG-байтов**, вытесняя самые давно использованные. Это лимит самих изображений; память Python, Pillow, шрифтов и двух рабочих изображений учитывается отдельно. Ключ включает версию шаблона, роль, группу, дату и фактические данные занятий и связанных подгрупп. При смене дизайна версия шаблона обновляется, поэтому старое оформление не переиспользуется. Telegram ID и исходные Excel-ячейки в ключ не входят. Значимые изменения дают другой ключ; неизменные данные переиспользуют одинаковые bytes между пользователями. Кеш исчезает после перезапуска, файловой очистки не требует.

До сериализации ограничены число занятий, подгрупп и длины полей, до рисования — точное соответствие группы/даты либо преподавателя/даты и допустимость модели. Ошибки карточек перехватываются отдельно и логируются только по классу исключения. Миграция схемы SQLite до версии 11 добавляет nullable-поле `notification_outbox.card_payload`; существующие задания остаются текстовыми. Новые настройки окружения, сервисы и внешние API не нужны.

## Предпросмотр и проверка

Из корня проекта с установленными зависимостями:

```powershell
.venv/Scripts/python.exe scripts/preview_schedule_cards.py
.venv/Scripts/python.exe -m pytest --basetemp=.pytest-tmp-cards
.venv/Scripts/python.exe -m ruff check --select F src tests scripts
.venv/Scripts/python.exe scripts/update_locks.py --check
.venv/Scripts/uv.exe build --wheel --out-dir data/card-build
```

Для Linux используйте `.venv/bin/python` и `.venv/bin/uv`. Скрипт предпросмотра печатает фактическое время генерации и размер каждого файла. Данные, имена и времена в демо синтетические; рабочую SQLite он не открывает.

| Пример | Что проверить |
| --- | --- |
| [Утверждённый день](examples/schedule-cards/approved-day.png) | Пять пар 28 октября 2026 для ИС-22; сравнение с приложенным эталоном, положение `ауд.` и `спортзал` |
| [Короткий день](examples/schedule-cards/short-day.png) | Только слоты 02 и 05 заняты; остальные позиции не сдвигаются, счётчик показывает 2 пары |
| [Длинные поля](examples/schedule-cards/long-fields.png) | Полный длинный предмет и ФИО, помещение `24а`, зазор перед временем |

`approved_demo_lessons()` в скрипте создаёт те же пять занятий, дату и группу, что и поставленный эталон. `short_demo_lessons()` и `long_fields_demo_lessons()` позволяют повторно использовать остальные демонстрации при проверках. Эти фикстуры не импортируются рабочим рендерером.

Проверка 25 октября 2026 после исправления отрисовки длинных названий и одиночных подгрупп: полный `pytest` — **765 passed, 2 skipped**. Ruff F и `compileall` прошли. После замены Rich Message на обычное фото тесты с настоящими типами запросов aiogram проверяют первоначальный `SendPhoto`, отдельный `SendMessage` по кнопке «Текст» и обратный `SendPhoto`. Дополнительно проверяются предупреждения об актуальности, длинный текст с кнопкой под последней частью и сохранение исходного сообщения при ошибках. Реальных запросов к Telegram эти проверки не выполняют.

После исправления отрисовки М-11, Ю-11 и Ю-12 на 26 октября локальная SQLite проверена в режиме чтения: созданы PNG для всех **28 из 28** расписаний на этот день и **168 из 168** сохранённых расписаний за 19–23 и 26 октября. Текстовых fallback в этой выборке нет. Три ранее проблемных PNG визуально проверены: длинное название М-11 помещается над помещением и преподавателем, обозначения подгрупп Ю-11 и Ю-12 сохранены. До последующего смещения названий все семь демонстрационных PNG после исправления побайтно совпали с предыдущим рендером, включая утверждённый день. Версия шаблона обновлена для сброса старых ключей кеша.

После смещения названий на 4 px вниз повторно отрисованы все 168 сохранённых расписаний; 67 тестов рендерера и Ruff F прошли. Длинные названия по-прежнему помещаются над нижней строкой. Версия шаблона той проверки — `schedule-cards-v3.3-title-offset`.

До смещения названий утверждённый день через встроенный рендерер пиксельно совпал с повторным запуском приложенного `render_reference.py` в этой среде. Визуально проверены оба изображения в исходном разрешении, включая положение `ауд.`/`спортзал`, выравнивание времени и зазор после ФИО. Сам поставленный `approved_reference.png` отличается от повторного запуска эталонного скрипта в метриках и растеризации текста. Среда той проверки — Windows, Python 3.12.10, Pillow 12.3.0, FreeType 2.14.3; RAQM отсутствует. Эти отличия наблюдаются уже в самостоятельном эталоне, до интеграции.

Wheel собран и установлен в отдельный каталог. Из этой установки проверены импорт бота, наличие обоих Nimbus и лицензии, кириллические глифы и RGB PNG 1080×1620; каталог исходников отсутствовал в `sys.path`.

После перехода на Python 3.14 локально собраны оба Docker-образа: `core` и полный вариант с Grok 1.0.62. Без сети проверены Python 3.14.9, импорт приложения, инициализация SQLite до схемы 10, генерация RGB PNG 1080×1620 с кириллицей под UID 1000, версия Grok и `pip check`. В `core` отдельно проверены отсутствие Grok и отключённые по умолчанию реакции. Реальная отправка в Telegram и запуск на VPS не проверялись.

В тестах используются синтетические `Lesson`, временные SQLite и подмены Telegram: проверяются нумерация, вставка классного часа до/между/после пар, сохранение пустых слотов, реальное длинное название М-11 и его зазор до плашки помещения, отображение одиночных подгрупп без потери или дублирования метки, переполнение, текстовый fallback для параллельных подгрупп и неоднозначных данных, владельцы меню, ошибки отправки, актуальность подписи, кеш, single-flight, таймауты, отмена и работа event loop во время рендера. Локальный рендер и подмены Telegram не подтверждают реальную отправку через Telegram.

Шрифты поставляются внутри wheel, поэтому контейнер не зависит от системных шрифтов. Pillow закреплён в `uv.lock`, runtime/dev экспорты обновляются штатным `scripts/update_locks.py`. Docker выполняет локальный smoke check рендера кириллицы после установки пакета; дополнительных загрузок шрифта при запуске нет.

После разрешённого деплоя на VPS проверьте карточку в личке и настроенной группе, возврат к меню, отказ чужому владельцу, подпись при устаревшем источнике и новую картинку после исправления аудитории. Отдельно проверьте, что уведомления, закрепление и Grok по-прежнему приходят текстом. Команды сборки без деплоя:

```sh
docker build --target core -t schedule-bot:cards-core .
docker build -t schedule-bot:cards .
docker run --rm --network none --entrypoint python schedule-bot:cards-core -c "from schedule_bot.bot.app import run_bot; from schedule_bot.card_renderer import IMAGE_SIZE; assert IMAGE_SIZE == (1080,1444)"
```
