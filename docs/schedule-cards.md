# Карточки расписания

В личном чате выберите профиль студента, откройте `/menu` → «Сегодня», «Завтра», выбранную дату или день из «Недели» → **«🖼 Карточка»**. В настроенном групповом чате путь тот же; кнопки меню доступны открывшему его участнику. При просмотре дня через нижнюю клавиатуру в личке появляется дополнительное сообщение с кнопкой карточки. Для «Недели» можно выбрать день отдельной inline-клавиатурой.

Бот отправляет PNG новым фото-сообщением. Текст и меню остаются доступны. Каждое нажатие заново получает текущие занятия через существующий `lessons_for`: группа или роль в callback не передаются. Если профиль или группа чата изменились, используются текущие настройки SQLite. Callback содержит владельца меню и ISO-дату, укладывается в лимит 64 байта.

## Дизайн и данные

Все карточки имеют размер **1080 × 1620**, RGB. Утверждённый вариант «Акцент на аудитории» рисуется в двойном разрешении, затем уменьшается LANCZOS. Фон — `#0C191E`, основной текст — `#F4F8F8`, вторичный — `#9EAFB4`, акцент — `#83DFD5`. Шесть слотов 01–06 имеют постоянные координаты: верхняя граница `510 + (номер − 1) × 176`, высота 160, границы по горизонтали `136…1024`. Номер слева берётся из `lesson_number`, а не `position`. Свободные слоты остаются на месте и содержат тире. Занятие не объявляется отменённым по отсутствию в снимке.

В шапке находятся группа, дата и день недели выбранного расписания. Две плашки показывают число реальных пар с правильным склонением и общий интервал занятий. Отдельной статистики окон, вертикальной шкалы, соединительных точек и полосок нет. Краткая характеристика дня зависит от нагрузки. Пять и шесть пар могут обозначаться как плотный учебный день; короткое расписание не получает такую подпись.

Предмет рисуется Nimbus Sans Bold, базовый размер 43 px. Внизу слева — плашка помещения и преподаватель, справа — время. Числовой номер аудитории выделен белым жирным шрифтом 27 px; приглушённый суффикс ` ауд.` расположен на 5 px ниже. `спортзал` остаётся обычным приглушённым текстом без суффикса. Существующие `ауд.`/`аудитория` нормализуются без дублирования; обозначения вроде `24а` сохраняются. При отсутствии помещения плашка не рисуется.

Время берётся исключительно из `Lesson.start_time/end_time`, которые заполняются действующим парсером Excel. Общий интервал показывается при известных корректных временах всех обычных пар. Неизвестные значения обозначаются явно. Демонстрационные часы не являются общим расписанием звонков.

Седьмая, восьмая и другие неподдерживаемые пары, несколько занятий или подгруппы в одном слоте и классный час получают существующий текстовый fallback. Их сведения не отбрасываются ради PNG: исходное текстовое расписание сохраняет предметы, преподавателей, помещения, время и связи подгрупп.

При слишком длинных полях, неподдерживаемых символах, неоднозначной нумерации, повторном номере, большем количестве подгрупп или нехватке места PNG не создаётся. Рендерер измеряет текст встроенным шрифтом и не обрезает сведения многоточием. Пустая выборка, включая неизвестную дату, получает текстовое пояснение вместо карточки с неподтверждённым выходным.

В профиле **преподавателя кнопка скрыта**: его день может содержать несколько групп на одной позиции, а макет рассчитан на одну учебную группу. Преподавательское текстовое расписание продолжает работать. Рассылки, outbox, закрепления и Grok сохраняют прежний текстовый формат.

Предупреждение о давности вычисляется через `with_freshness` при каждой отправке и находится только в подписи Telegram. Оно не сохраняется внутри PNG или в ключе кеша. Подпись короткая, без HTML и пользовательских полей. Карточка не содержит выдуманного времени обновления.

## Модули и ограничения ресурсов

| Файл | Назначение |
| --- | --- |
| `src/schedule_bot/card_renderer.py` | Чистое преобразование `Lesson` в модель слотов, затем Pillow → PNG bytes; без SQLite, Telegram и сети |
| `src/schedule_bot/card_service.py` | Общий для пользователей кеш и ограничение фонового рендера |
| `src/schedule_bot/bot/cards.py` | Проверка действия, чтение текущего расписания, подпись и отправка фото, обработка ошибок |
| `src/schedule_bot/bot/{app,groups,menus}.py` | Кнопки и существующие проверки владельца и профиля |
| `src/schedule_bot/assets/fonts/` | Nimbus Sans Regular/Bold, исходная лицензия `FONT_LICENSE.txt`, источники и контрольные суммы |

Pillow выполняется через `asyncio.to_thread`. В одном процессе одновременно работают максимум **2 генерации**, очереди новых ключей нет: при занятости пользователь получает предложение повторить запрос. На один ключ допускается максимум **8 ожидающих запросов**, разделяющих одну генерацию. Дедлайн ответа — **8 секунд**. Таймаут или отмена запроса не освобождает слот до фактического завершения потока: следующие запросы не создают лишних фоновых работ. При штатной остановке бот дожидается этих работ.

LRU хранит максимум **32 PNG и 16 МиБ суммарных PNG-байтов**, вытесняя самые давно использованные. Это лимит самих изображений; память Python, Pillow, шрифтов и двух рабочих изображений учитывается отдельно. Ключ включает версию шаблона, роль, группу, дату и фактические данные занятий и связанных подгрупп. При смене дизайна версия шаблона обновляется, поэтому старое оформление не переиспользуется. Telegram ID и исходные Excel-ячейки в ключ не входят. Значимые изменения дают другой ключ; неизменные данные переиспользуют одинаковые bytes между пользователями. Кеш исчезает после перезапуска, файловой очистки не требует.

До сериализации ограничены число занятий, подгрупп и длины полей, до рисования — точное соответствие группы/даты и допустимость модели. Ошибки карточек перехватываются отдельно и логируются только по классу исключения. Новые настройки окружения, таблицы SQLite, сервисы и внешние API не нужны.

## Предпросмотр и проверка

Из корня проекта с установленными зависимостями:

```powershell
.venv/Scripts/python.exe scripts/preview_schedule_cards.py
.venv/Scripts/python.exe -m pytest --basetemp=.pytest-tmp-cards
.venv/Scripts/python.exe -m ruff check --select F src tests scripts
.venv/Scripts/python.exe scripts/update_locks.py --check
.venv/Scripts/uv.exe build --wheel --out-dir data/card-build
```

Для Linux используйте `.venv/bin/python` и `.venv/bin/uv`. Скрипт предпросмотра печатает фактическое время генерации и размер каждого файла. Данные, имена и времена в демо синтетические; рабочую SQLite он не открывает.

| Пример | Что проверить |
| --- | --- |
| [Утверждённый день](examples/schedule-cards/approved-day.png) | Пять пар 28 октября 2026 для ИС-22; сравнение с приложенным эталоном, положение `ауд.` и `спортзал` |
| [Короткий день](examples/schedule-cards/short-day.png) | Только слоты 02 и 05 заняты; остальные позиции не сдвигаются, счётчик показывает 2 пары |
| [Длинные поля](examples/schedule-cards/long-fields.png) | Полный длинный предмет и ФИО, помещение `24а`, зазор перед временем |
| [Ко второй паре](examples/schedule-cards/second-pair.png) | Слот 01 пустой, пары находятся в 02 и 03 |
| [Окно между парами](examples/schedule-cards/gap-between-pairs.png) | Пары 02 и 04, пустой слот 03 |
| [Плотный день](examples/schedule-cards/dense-day.png) | Все шесть слотов на тех же координатах, длинные названия помещаются |

`approved_demo_lessons()` в скрипте создаёт те же пять занятий, дату и группу, что и поставленный эталон. `short_demo_lessons()` и `long_fields_demo_lessons()` позволяют повторно использовать остальные демонстрации при проверках. Эти фикстуры не импортируются рабочим рендерером.

Проверка 25 октября 2026: полный `pytest` — **724 passed, 2 skipped**; после последнего уточнения нормализации спортзала профильные тесты карточек — **95 passed**. Ruff F, `compileall`, проверка lock-экспортов и совместимости 44 установленных пакетов прошли. Все шесть PNG созданы через рабочие `normalize_schedule()` и `render_card()`.

Утверждённый день через встроенный рендерер пиксельно совпал с повторным запуском приложенного `render_reference.py` в этой среде. Визуально проверены оба изображения в исходном разрешении, включая положение `ауд.`/`спортзал`, выравнивание времени и зазор после ФИО. Сам поставленный `approved_reference.png` отличается от повторного запуска эталонного скрипта в метриках и растеризации текста. Локальная среда — Windows, Python 3.12.10, Pillow 12.3.0, FreeType 2.14.3; RAQM отсутствует. Эти отличия наблюдаются уже в самостоятельном эталоне, до интеграции.

Wheel собран и установлен в отдельный каталог. Из этой установки проверены импорт бота, наличие обоих Nimbus и лицензии, кириллические глифы и RGB PNG 1080×1620; каталог исходников отсутствовал в `sys.path`. Docker CLI в этой среде отсутствует, поэтому контейнер не собирался. Реальная отправка в Telegram и VPS не проверялись.

В тестах используются синтетические `Lesson`, временные SQLite и подмены Telegram: проверяются нумерация, сохранение пустых слотов, переполнение, текстовый fallback для подгрупп и классных часов, владельцы меню, ошибки отправки, актуальность подписи, кеш, single-flight, таймауты, отмена и работа event loop во время рендера. Локальный рендер и подмены Telegram не подтверждают реальную отправку через Telegram.

Шрифты поставляются внутри wheel, поэтому контейнер не зависит от системных шрифтов. Pillow закреплён в `uv.lock`, runtime/dev экспорты обновляются штатным `scripts/update_locks.py`. Docker выполняет локальный smoke check рендера кириллицы после установки пакета; дополнительных загрузок шрифта при запуске нет.

После разрешённого деплоя на VPS проверьте карточку в личке и настроенной группе, возврат к меню, отказ чужому владельцу, подпись при устаревшем источнике и новую картинку после исправления аудитории. Отдельно проверьте, что уведомления, закрепление и Grok по-прежнему приходят текстом. Команды сборки без деплоя:

```sh
docker build --target core -t schedule-bot:cards-core .
docker build -t schedule-bot:cards .
docker run --rm --network none --entrypoint python schedule-bot:cards-core -c "from schedule_bot.bot.app import run_bot; from schedule_bot.card_renderer import IMAGE_SIZE; assert IMAGE_SIZE == (1080,1620)"
```
